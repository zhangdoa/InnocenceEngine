## Port strategy decision

**Pick: C — keep current Pass-class wrapping, replace per-pass HLSL bodies with Capsaicin code (selectively, per stage).**

Justification:
- Capsaicin is a monolithic `gi1.comp` containing ~50 kernels selected via `#define`s plus a single `gi1.cpp` orchestrator. Option A (file-by-file mirror) requires either ingesting a 4000-line shader into our build (the engine has no per-kernel `#define`-selection layer, see `Source/Shaders/HLSL/` flat-per-pass convention) or splitting `gi1.comp` into ~10 files anyway — at which point Option C delivers the same code with the engine's idioms preserved.
- The engine's `RenderPassComponent` / `CommandListComp` / `WaitIfActive` graph wiring in `ExecuteCommands_GI.cpp` is paper-orthogonal scaffolding. Discarding it (Option A or B) buys nothing and forces re-binding hundreds of texture slots.
- Option B (rewrite from scratch with reference as spec) is what TASK-114–118 did already and the umbrella's existence is evidence it failed.
- Five of ten stages are already paper-aligned (#4, #6, #9, #10) or aligned-enough (#7's denoiser_hint shape). The work concentrates in stages #1, #2, #3, #5, #7-flat-vs-bent, #8 — exactly the stages where Option C's per-pass HLSL replacement is the surgical move.
- Under PT-primary (state/project-direction.md, 2026-04-30) the rasterization-side cache is fallback / debug-comparison only. The quality bar is "match Capsaicin on Sponza", not "compete with PT". Umbrella AC #4 (visual parity) is achievable; AC #5 (60 FPS) is contingent on Stage #5's 16→64 ray-count jump and the SH→bent-cone integration cost — both flagged.

Acknowledgement on umbrella ACs: AC #5 (60 FPS) is **at risk** under the ray-count and bent-cone changes. A 4× ray-count increase plus per-probe parallel-scan CDF construction is the dominant cost increase; baseline measurement should land first (TASK-226.2) before locking the AC. Recommend re-scoping AC #5 to "no regression vs current rasterizer baseline" if the perf falls short and rasterizer-fallback quality is good-enough.
