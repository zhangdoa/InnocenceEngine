## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The Assimp importer in AssimpImporter.cpp does not use aiProcess_PreTransformVertices, so glTF node transforms (rotation, translation, scale) are NOT baked into vertex positions. This means any model that relies on per-node rotations (e.g. NewSponza_Curtains_glTF where fabric panels are modeled flat and oriented by node transforms) will import with incorrect geometry.

Current workaround: scene-level TransformComponent rotation for the curtains (TASK-14). But this is a blunt fix — it applies a single rotation to all curtain meshes, which is incorrect if individual meshes have different per-node orientations.

**Proper fix:** Add aiProcess_PreTransformVertices to the Assimp import flags in Source/Engine/ThirdParty/AssimpWrapper/AssimpImporter.cpp. This bakes all accumulated node transforms into vertex positions, producing world-space vertex data.

**Consequence:** All previously imported .innobin mesh files become stale and must be regenerated by re-running the import on all original assets. The scene-level curtains transform (GISponza.Curtains.TransformComponent) should be reverted to identity after re-import, since the transforms will be baked into the mesh data.
